## Parallax clamping prevents accumulation

The accelerometer listener now includes a clamp:

```kotlin
currentParallaxX = (currentParallaxX * 0.9f + x * 0.1f).coerceIn(-1f, 1f)
```

This bounds the smoothed tilt value to `[-1, 1]`, preventing the unbounded accumulation identified in the prior review.

## Word-by-word headline reveal skipped

The design called for word-by-word headline reveal with 80ms stagger. The implementation animates the entire TextView at once (1000ms delay, 30dp slide-up with fade). This is a minor deviation that produces a similar visual effect with less complexity and is acceptable.

## Shine and ember animations not tracked for cancellation

The shine pulse animations (`startShinePulse`) and ember restart logic (`animateEmber` end listener) use `b.root.postDelayed` to re-schedule themselves and check `isDestroyed` before posting the next cycle. The animator sets are not added to the `animators` list, so `onDestroy` cannot proactively cancel in-flight shine or ember-restart animations. If the activity is destroyed mid-pulse, the animation will complete its current cycle (up to 1200ms for shine, up to 12s for an ember) before the `isDestroyed` check stops it. This is not a memory leak (the animators do not hold strong references to the activity's views), but the animations will consume CPU/GPU cycles for a short period after the activity is destroyed.

## Headline shimmer and underline not implemented

The design called for a shimmer sweep and animated underline on the "been waiting" span. The implementation applies only the cyan ForegroundColorSpan. Adding the shimmer and underline would require custom span rendering or a more complex layout (separate TextViews with clip masks). The current implementation is acceptable.
