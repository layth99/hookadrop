# HookaDrop Notification System — Implementation Plan

> Generated by the planning agent. FEAT artifacts are the authoritative decomposition;
> this flat plan is the fallback for the single-loop implementer.

## Codebase findings summary

| Area | Current state |
|------|--------------|
| Backend | No notification model, no notification routes, no FCM dependency. `services/` directory does not exist. ES modules throughout. |
| `models/User.js` | Missing `fcmToken` and `notificationsEnabled` fields. |
| `controller/orders.js` | `updateOrderStatus` — status saved at line ~154 after `order.save()`. `createOrder` — order saved at line ~47. Both need `setImmediate` hooks. |
| `controller/product.js` | `createProduct` — product saved at line ~142. Needs `notifyNewProduct` hook after `product.save()`. |

| `routes/stripe.js` | `confirm-payment` and webhook `payment_intent.succeeded` need `notifyPaymentSuccess`. Webhook `payment_intent.payment_failed` needs `notifyPaymentFailed`. |

      Verify: `node -e "import('firebase-admin').then(() => console.log('ok'))"` — prints `ok`.

      ```js
      notificationsEnabled:{ type: Boolean, default: true },
      ```
      Files: `models/User.js`
      Verify: `node server.js` starts without error; `db.users.findOne()` shows new fields (null / true) when a new user is created.

- [ ] 3. **Create `models/Notification.js`**
      Mongoose model with fields: `user` (ObjectId→User, required, index), `type` (enum: order/security/product/promo/account), `title`, `message`, `entityId` (String|null), `entityType` (enum: order/product/promo/user/null), `isRead` (Boolean default false), `metadata` (Object default {}), `createdAt` (Date default now). Compound index `{user:1, createdAt:-1}`.
      Files: `models/Notification.js` (new)
      Verify: `node server.js` starts; `db.notifications.findOne()` returns null without error.

- [ ] 4. **Create `services/fcmService.js`**
      Lazy Firebase Admin init (guard with `admin.apps.length`). Reads `FCM_SERVICE_ACCOUNT_KEY` (JSON string) and `FIREBASE_PROJECT_ID` from env. Exports `sendPushNotification(token, title, body, data={})` and `sendMulticastNotification(tokens[], title, body, data={})`. Both return `{success:boolean}` and never throw; missing config → log warning + return `{success:false}`.
      Files: `services/fcmService.js` (new)
      Verify: `node server.js` starts and logs `[FCM] not configured` warning if env vars are absent (no crash).

- [ ] 5. **Create `services/notificationService.js`**
      Exports: `createNotification`, `notifyOrderUpdate`, `notifyOrderPlaced`, `notifyPaymentSuccess`, `notifyPaymentFailed`, `notifyNewProduct`, `notifyPromoApplied`, `notifySecurityEvent`, `notifyProfileUpdated`. All fire-and-forget safe. See FEAT-001 step 5 for exact message templates. Messages include the order's `orderId` short ID (e.g. `order.orderId`, not MongoDB _id).
      Files: `services/notificationService.js` (new)
      Verify: `node server.js` starts without error.

- [ ] 6. **Create `routes/notifications.js`**
      User routes (all behind `protectRoute`):
      - `GET /` → paginated list (page, limit params)
      - `GET /unread-count` → `{success, count}`
      - `PATCH /:id/read` → mark one read (ownership check)
      - `PATCH /read-all` → mark all read for req.user
      - `DELETE /:id` → delete one (ownership check)
      - `PATCH /preferences` → update fcmToken + notificationsEnabled
      - `GET /preferences` → return current preferences
      Admin routes (behind `protectRoute + requireRole('admin')`):
      - `GET /admin/all` → paginated all-users notifications with user populated
      - `POST /admin/broadcast` → create notifications for all eligible users + FCM multicast
      Files: `routes/notifications.js` (new)
      Verify: `node server.js` starts; `GET /api/notifications` with valid JWT → `{success:true, data:[], unreadCount:0}`.

- [ ] 7. **Mount notifications route in `server.js`**
      Add import and `app.use('/api/notifications', notificationRoutes)` before the 404 catch-all.
      Files: `server.js`
      Verify: `GET /api/notifications` returns 200 (not 404).

## Ordering constraints

Steps 1–7 must complete before 8–13 (services must exist before being imported in controllers). Steps 14–18 (Android Gradle setup) must complete before steps 19–27 (they depend on FCM classes being available). Steps 28–30 (dashboard) depend only on step 6–7 (backend API). Steps 8–13 (controller hooks) are independent of each other and can be done in any order after step 5. Steps 19–27 (Android features) are independent of each other after step 18 and can be done in any order.

## Required manual actions (cannot be automated)

1. **Firebase project**: Create a Firebase project at https://console.firebase.google.com, register the Android app with package name `com.hookahdrop.app`, download `google-services.json`, and place it at `hookaDrop App/HookahDrop/app/google-services.json`.
2. **FCM service account**: In Firebase Console → Project Settings → Service Accounts → Generate new private key. Copy the JSON content into `.env` as `FCM_SERVICE_ACCOUNT_KEY='<single-line JSON>'` and set `FIREBASE_PROJECT_ID=your-project-id`.
3. **Push notification testing**: Real push notifications require a physical device or an emulator with Google Play Services.
